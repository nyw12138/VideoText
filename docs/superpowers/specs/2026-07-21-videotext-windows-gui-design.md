# VideoText Windows 图形工具设计

## 1. 背景与目标

现有 `videotext` 是可正常运行的 Windows 命令行工具，可接收 Bilibili、抖音和 YouTube 等公开单视频链接，下载音频、调用 FFmpeg 标准化、使用 faster-whisper 在 NVIDIA GPU 上转写，并导出 TXT、SRT 和 JSON。

本次目标是在当前 Windows 电脑上增加独立图形窗口。用户日常使用时只需粘贴网址并点击“开始转换”，不再打开 PowerShell、激活虚拟环境或输入命令。现有命令行入口继续保留。

## 2. 已确认范围

- 仅支持当前 Windows 电脑，不制作通用安装包，不处理跨设备部署。
- 使用独立 Windows 窗口，不采用浏览器界面。
- 提供实用版界面：默认一键转换，高级设置可折叠。
- 复用现有下载、音频处理、转写和导出服务，不复制业务逻辑。
- GPU 转写在独立工作进程中执行，避免原生 CUDA/CTranslate2 崩溃导致 GUI 一同退出。
- 第一版一次只运行一个任务，不实现队列、账号、历史数据库或批量链接。

## 3. 方案选择

### 3.1 选择 Tkinter/ttk

界面使用 Python 标准库 Tkinter/ttk。它不引入 PySide6 等大型依赖，适合当前单机工具的输入框、按钮、进度、日志和设置控件。界面风格以清晰、稳定、符合 Windows 使用习惯为目标，不追求复杂动画。

### 3.2 不直接在 GUI 进程中转写

GUI 不直接加载 faster-whisper。它启动隐藏的工作子进程，由工作进程调用 `VideoTextService`。这样即使 CTranslate2 或 CUDA 发生 Windows 原生访问冲突，GUI 仍能根据子进程退出码显示错误。

### 3.3 不通过解析现有 CLI 文本通信

GUI 与工作进程使用每行一个 JSON 对象的 JSON Lines 协议。现有 CLI 的彩色文字仅供人工阅读，不作为程序接口，以免文字变化破坏 GUI。

## 4. 总体架构

```text
桌面快捷方式
    ↓
pythonw.exe -m videotext.gui
    ↓
Tkinter GUI
    ├── URL 校验与设置管理
    ├── 进度、日志、耗时与结果按钮
    └── 隐藏启动 worker 子进程
            ↓ JSON Lines
        videotext.worker
            ↓
        VideoTextService
            ├── yt-dlp 解析与下载
            ├── FFmpeg 标准化
            ├── faster-whisper GPU 转写
            └── 原子导出结果
```

建议新增模块：

- `videotext.gui`：窗口布局、控件状态和主事件循环。
- `videotext.gui_controller`：任务启动、消息消费、停止与结果状态，便于脱离真实窗口测试。
- `videotext.worker`：接收任务参数、调用服务、输出 JSON Lines。
- `videotext.settings`：读取和原子保存本机 GUI 设置。
- `videotext.protocol`：定义并校验 GUI 与 worker 的消息结构。

现有 `service.py`、`downloader.py`、`audio.py`、`transcriber.py` 和 `exporters.py` 继续作为唯一业务实现。

## 5. 窗口与交互

窗口标题为“VideoText 视频转文字”。主区域包含：

1. 视频网址输入框，支持粘贴包含 `&` 的完整链接。
2. “开始转换”和“清空”按钮。
3. 默认折叠的“高级设置”。
4. 当前阶段、动态进度条和已用时间。
5. 简短的阶段日志。
6. “打开输出目录”“打开 TXT”“停止任务”和“复制详细信息”按钮。

高级设置包含：

- 模型：默认 `large-v3-turbo`，提供 `medium`。
- 语言：默认自动检测，提供中文和英文。
- 输出目录：默认项目 `outputs`，支持目录选择。
- 保留标准化音频：默认关闭。
- 覆盖已有结果：默认关闭。
- 完成后自动打开输出目录：默认开启。

首次打开时焦点位于网址输入框。按 Enter 等同于点击“开始转换”。任务运行时禁用会改变任务参数的控件，任务结束后恢复。

## 6. 任务生命周期

### 6.1 启动

GUI 先去除网址首尾空白并调用现有 URL 校验。校验通过后生成唯一任务 ID，为该任务创建专属临时根目录：

```text
%TEMP%\videotext-gui\<任务ID>
```

GUI 将任务参数写入专属临时目录中的 UTF-8 JSON 请求文件，再使用参数列表（而非 shell 命令字符串）启动当前虚拟环境的 `python.exe -m videotext.worker --request <文件>`。Windows 启动参数隐藏子进程控制台，并为标准输入、标准输出和标准错误建立管道。URL 中的 `&`、`?` 等字符只存在于 JSON 中，不会被 PowerShell 解释。

### 6.2 运行

worker 调用现有服务，并将阶段事件转换为 JSON Lines。第一版显示以下离散阶段：

```text
读取媒体信息 → 下载音频 → 标准化音频 → GPU 转写 → 写入结果
```

由于现有转写引擎不提供可靠的百分比，第一版在当前阶段使用不定进度条，不显示虚假百分比。已完成阶段显示对勾，并持续显示真实已用时间。

### 6.3 完成

worker 返回输出文件绝对路径和耗时。GUI 显示成功状态，启用“打开 TXT”和“打开输出目录”，并根据设置决定是否自动打开输出目录。

### 6.4 停止

点击“停止任务”后，GUI 通过 worker 标准输入发送 `{"type":"cancel"}`。worker 的控制线程设置取消标记，业务流程在各阶段边界检查该标记并正常退出。若 worker 正在不可中断的 GPU 调用中，超过 5 秒宽限期后 GUI 终止子进程。子进程退出后，GUI 只清理该任务的专属临时根目录，不触碰正式输出、其他任务目录或 Hugging Face 模型缓存。

窗口关闭时若任务仍在运行，必须确认“关闭将停止当前转换”。

## 7. 通信协议

GUI 到 worker 的初始任务参数使用 JSON 请求文件，运行期取消命令使用标准输入 JSON Lines。worker 的标准输出只写 UTF-8 JSON Lines；诊断文字写入日志或标准错误。消息至少包括：

```json
{"type":"progress","stage":"download","message":"正在下载音频"}
{"type":"completed","elapsed":106.0,"paths":["C:\\...\\transcript.txt"]}
{"type":"error","code":"download_failed","message":"音频下载失败","hint":"请检查链接和网络"}
```

允许的消息类型为：

- `started`：worker 已启动并返回任务 ID。
- `progress`：阶段更新。
- `completed`：成功及输出路径。
- `error`：可预期错误及建议。
- `diagnostic`：可选诊断信息，不直接作为普通用户提示。

GUI 必须忽略未知字段；遇到无法解析的整行内容时记录日志，并在进程结束后报告工作进程协议错误。

## 8. 设置与日志

GUI 设置保存到：

```text
%LOCALAPPDATA%\VideoText\settings.json
```

设置文件使用临时文件加替换的方式原子写入。仅保存模型、语言、输出目录、复选框和窗口几何信息，不保存视频网址、Cookie、令牌或转写文本。设置损坏时回退默认值并记录警告，不阻止程序启动。

日志保存到：

```text
%LOCALAPPDATA%\VideoText\logs\videotext.log
```

日志记录时间、阶段、错误类型、退出码和堆栈，但沿用现有敏感字段清理原则，不记录 Cookie、Authorization 或 token。日志采用大小限制和轮转，避免无限增长。

## 9. 错误处理

GUI 将错误转换为简明中文提示，同时保留“复制详细信息”：

- URL 无效：提示粘贴完整的单视频链接。
- 平台解析失败：提示检查视频是否公开，并建议更新 yt-dlp。
- 下载或网络失败：允许原参数重试。
- FFmpeg 不可用：明确显示环境检查建议。
- CUDA/cuDNN 不可用：提示检查 GPU 环境。
- 显存不足：建议将模型切换为 `medium`。
- 输出已存在：建议勾选覆盖或更换输出目录。
- worker 返回普通异常：显示错误消息和建议。
- worker 原生崩溃：GUI 根据非正常退出码提示“GPU 转写进程异常退出”，自身保持可用。
- 用户停止：显示“任务已停止”，不作为错误弹窗。

任务无论成功、失败还是停止，GUI 都必须恢复可编辑状态，不能永久停留在“运行中”。

## 10. 启动方式

项目增加 `videotext-gui` 入口用于开发和诊断。日常启动使用桌面快捷方式，目标为当前项目虚拟环境中的 `pythonw.exe` 和 GUI 模块，因此不会显示 PowerShell，也不需要手动激活 `.venv`。

命令行入口 `videotext` 保持原状，继续支持自动化和故障诊断。

## 11. 测试策略

自动化测试不访问真实视频平台、不运行 FFmpeg、不加载 GPU 模型。通过假的 worker、服务和文件系统边界覆盖：

- URL 输入、Enter 启动和包含 `&` 的链接。
- 高级设置到 worker 请求的映射。
- 设置保存、恢复、损坏回退和敏感字段排除。
- JSON Lines 的编码、解析、未知字段和损坏消息。
- 各阶段的 GUI 状态变化。
- 运行期间控件禁用以及完成后的恢复。
- 成功后输出路径按钮。
- 可预期错误、非零退出码和 Windows 原生崩溃码。
- 停止、强制终止和专属临时目录清理。
- 关闭运行中窗口的确认流程。
- 现有 CLI 与业务层测试全部继续通过。

人工验收使用一个有权处理的短视频链接，验证桌面快捷方式启动、GPU 转写、结果打开、停止任务和窗口关闭行为。

## 12. 验收标准

1. 双击桌面快捷方式可打开独立窗口，不显示 PowerShell。
2. 粘贴完整网址并点击一次即可完成转换。
3. 含 `&` 的网址可正常提交。
4. 窗口在下载和 GPU 转写期间保持响应。
5. 成功后可直接打开 TXT 和输出目录。
6. 高级设置能正确控制模型、语言、目录、保留音频和覆盖行为。
7. 工作进程普通报错或原生崩溃时 GUI 不退出，并给出可理解提示。
8. 停止任务后只清理本任务临时文件。
9. 重启 GUI 后恢复上次非敏感设置。
10. 原有 `videotext` 命令行功能与测试不受影响。

## 13. 非目标

第一版不包含：

- 多任务队列或批量链接。
- 转写历史数据库和全文检索。
- 在线账号、权限、云同步或网页服务。
- 自动安装或升级显卡驱动、CUDA、cuDNN、FFmpeg。
- 打包成可分发给其他电脑的独立安装程序。
- 登录后内容、付费内容、DRM 或平台限制绕过。
